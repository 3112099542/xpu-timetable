# M2-B 抓包指引：一次真实的教务课表会话

> 目的：拿到「一网通办 → 登录 → 进入课表 → 课表数据加载」这一条链路的**真实请求与响应样本**，
> 用它能一次性确定：端点 URL、数据形态（JSON 还是页面 HTML）、鉴权是否只靠 Cookie。
> 之后 `parser/xpu` 才能照着真实字段写（在此之前写就是猜）。
>
> **隐私提醒（先看这条）**：抓包文件里会包含你的**学号、姓名、Cookie/会话令牌**。
> 本项目是开源项目，所以：**抓包文件只放进本机项目目录用于本地分析，不要提交到 GitHub**；
> 我分析时只提取「接口路径 + 字段结构」，并把样本**脱敏后**才放进测试 fixture。
> 分析完你可以自行删除该文件（我不会删你的东西，只会告诉你路径）。

## 一、抓哪些内容（按重要性排序）

| # | 要抓的东西 | 为什么要 |
|---|-----------|---------|
| 1 | **完整 HAR 文件**（含登录前后的所有请求） | 端点、参数、响应体、Cookie 全在里面，是主材料 |
| 2 | **每一步的地址栏 URL**（登录前 → 登录后 → 课表页） | 决定 `XpuEndpoints.kt` 里的 URL 特征正则 |
| 3 | **课表页面截图**（手机或电脑） | 校对我们解析出的课程条数与页面实际是否一致 |

| 5 | 课表页是否需要**再次登录/滑块/短信** | 决定 WebView 方案里用户要手动做几步 |

**抓取范围**：从打开 `https://sz.xpu.edu.cn/` 开始 → 完成登录 → 进入「我的课表/课表查询」→ 等课表**完全显示出来**。
过程中不要中途关页面（HAR 会断）。

## 二、两种抓法（选一种即可）

### 方案 1（首选，最简单）：电脑浏览器导出 HAR
> 需要电脑与学生同一网络环境（校园网或 VPN），能用浏览器打开 sz.xpu.edu.cn。

1. 电脑上用 **Chrome / Edge** 打开 `https://sz.xpu.edu.cn/`
2. 按 `F12` 打开开发者工具 → 切到 **Network（网络）** 面板
3. **勾上 `Preserve log`（保留日志）** ← 关键，否则跳转后前面的请求会丢
4. 保持面板打开，正常完成：登录 → 找到课表入口 → 打开课表 → 等课表显示完整
5. 在 Network 面板任意位置**右键 → `Save all as HAR with content`**（Chrome 中文版：「将所有内容另存为 HAR」）
6. 把导出的 `.har` 文件放到项目里：`docs/fixtures/capture/`（目录没有就新建）

**注意**：电脑浏览器的 User-Agent 与手机不同。如果发现「电脑上能看到课表、但手机端页面不一样」，我们再补一次手机抓包（方案 2）。

### 方案 2（更贴近 App 环境）：手机 Chrome + 电脑远程调试
1. 手机用 **Chrome** 打开 `https://sz.xpu.edu.cn/` 并登录到课表页
2. 手机用 USB 连电脑（USB 调试已开 ✓）
3. 电脑 Chrome 打开 `chrome://inspect/#devices` → 找到手机上的那个标签页 → 点 `inspect`
4. 在弹出的 DevTools 里切到 **Network** → 勾 `Preserve log` → **在手机上刷新课表页**
5. 同样右键 `Save all as HAR with content` → 放到 `docs/fixtures/capture/`

> 说明：这一路径抓到的 User-Agent 是手机端的，与 App 内 WebView 最接近，解析适配风险最低。

## 三、如果你只想给我最少的信息（应急版）

不导出 HAR 也可以，但需要你手动抄三样东西（信息可能不全，我可能要再问）：

1. 登录完成后，**课表页面的完整 URL**（地址栏复制）
2. 按 `F12 → Network`，在课表页**刷新一次**，然后找到**返回课程数据的那个请求**（通常响应里能看到课程名、教室、周次）：
   - 它的 **Request URL**（完整）
   - 它的 **Response** 内容（右键 → Copy response，粘贴给我）
3. 课表页截图

## 四、我拿到之后会做什么（让你知道后续流程）

1. **分析 HAR**：定位课表数据请求 → 判断是 JSON 接口还是服务端渲染 HTML → 如果多条候选，按"响应体里含课程名/周次"筛选
2. **产出三件东西**：
   - `XpuEndpoints.kt` 的准确内容（登录 URL、课表接口 URL 正则、域名常量）
   - 策略判定：走**策略 A（拦截 XHR/JSON）**还是**策略 B（DOM 注入解析）**，并说明依据
   - **脱敏后的金样本**（`parser/xpu/fixtures/sample_schedule.json`），学号/姓名替换为占位符，作为回归测试固定数据
3. **写给编码 agent 的实现规格**（`docs/tasks/M2-B-教务直连实现规格.md`），再由它实现 `parser/xpu` + WebView 捕获 + 预览确认接线

## 五、我这边的环境准备（不需要你操作）

## 六、Firefox 专用步骤（老大当前环境，2026-09-17 实测确认）

> 已确认现状：Firefox 已打开 `https://sz.xpu.edu.cn/auth2/login`，DevTools 网络面板已开启。

1. **先勾「保留日志」**：网络面板**右上角齿轮 ⚙**（网络设置）→ 勾选 **「保留日志」（Persist Logs）**
   ⚠️ 必须**在登录之前**勾，否则登录跳转会把前面的请求清空、拿不到重定向链
2. **保持 DevTools 打开**，正常走完：登录（含滑块）→ 进入「我的课表/课表查询」→ **等课表完全显示出来**
3. **如果中途弹出了新标签页**（一网通办常在新标签里打开教务系统）：
   在新标签按 `Ctrl+Shift+I` 打开 DevTools → 切到「网络」→ **同样勾上「保留日志」** → 刷新一次课表页并等它加载完
4. **导出 HAR**：在网络请求列表里**任意位置右键 → 「全部另存为 HAR」**
   保存到项目目录：`docs/fixtures/capture/`（该目录已被 .gitignore 忽略，不会进 GitHub）
5. **补充步（很重要，HAR 有时不含响应体）**：
   - 在网络面板顶部筛选里**只勾 `XHR`**
   - 找到**返回课程数据**的那个请求（判断方法：点它 → 右侧「响应」里能看到课程名/星期/节次/周次等字样，或是一大段 JSON；也可以按「大小」列排序，取最大的那个 JSON）
   - 右键该请求 → 「**复制 → 复制响应**」→ 粘贴保存为 `docs/fixtures/capture/schedule_response.json`
6. **若筛 XHR 找不到课程数据**（说明课表是服务端渲染的 HTML）：
   把课表页那条 `文档(document)` 请求的响应按同样方式复制保存为 `docs/fixtures/capture/schedule_page.html`
7. **再给我**：① 登录后课表页的截图 ② 你数一下课程条数（如「12 门 / 18 条」）
8. 全部放到 `docs/fixtures/capture/` 后告诉我，我来分析
