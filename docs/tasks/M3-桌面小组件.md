# M3 任务规格：桌面小组件（今日课程，Glance）

> 里程碑命名：Spec §3 的 P1 清单把「桌面小组件（今日课程）」定义为 **M3**，本文件按其命名。
> 目标：一个只读的桌面卡片，**打开手机就能看到今天上什么课、下一节是哪个**，不用打开 App。
>
> **唯一新增依赖是 Glance + WorkManager 两项**（版本已实测可用，见 §1）。不改表结构，不动已验收的提醒/导入/导航链路。

---

## 0. 验收标准（Spec §9 原文，P1）

| 编号 | 原文 |
|------|------|
| **AC-17** | When 桌面已添加小组件且当天有课，系统**必须**按时间列出今日课程并高亮下一节 |
| **AC-18** | When App 内导入或编辑课程保存完成，小组件**必须**立即刷新（不等系统刷新周期） |
| **AC-19** | If 今日无课（含单双周判定为无课），小组件**必须**显示「今天没有课」而非列出非本周课程 |

即：**完整数据链路是「今日课程列表 + 下一节高亮 + 空态 + 数据变更即时刷新 + 跨天刷新」**。

3. 若 Gradle 解析失败，**只改 catalog 一处**并回写架构 §4.1（活规格纪律）。

> 备选是复用既有 AlarmManager 链路（零新依赖，但要自己处理重启/时区）。**本规格按 WorkManager 实现**——
> 它自带持久化与重启后恢复，且架构早已把 2.11.2 列进依赖清单；代价是 APK 约 +0.4~0.6 MB。

## 2. 数据来源与口径（已核实，别自己发明）

- **今日课程 = `repository.observeWeek(termId, currentWeek)` 的结果里筛 `session.dayOfWeek == 今天`**。
  - `observeWeek` 的周次过滤**已经在 SQL 层完成**（`CourseSessionDao.observeWeekSessions`：`week_list` 优先，否则 `start_week..end_week` + `UPPER(week_type)` 单双周判定）
    → 所以 **AC-19 的「含单双周判定为无课」天然成立**，不要在 UI 层再做一遍周次过滤（重复过滤是本项目踩过的坑）。
  - 周次用 `WeekCalc.currentWeek(termStartDate, LocalDate.now())`（纯函数，开学前返回 `null`）。**返回 null 时按「不在学期周内」处理**：显示空态文案「今天没有课」（或「学期未开始」——二选一，规格取**前者**，简单一致）。
  - 节次时间用 `repository.observeTimeSlots()` 的 `TimeSlot(section, startMinute, endMinute)`。
- **无激活学期**（`observeActiveTerm()` 为 null）→ 显示空态「还没有课表，打开 App 导入」。

### 2.1 高亮规则（必须写成可单测的纯函数）

「下一节」的定义**与提醒链路保持一致：尚未结束的第一门课**（不是"还没开始"）：

```
按 start_section 升序 → 取第一门满足 nowMinute < endMinute(session.endSection) 的课为「下一节/当前」
若全部已结束 或 今日无课 → 无高亮
```

好处：上课期间（如 19:05 时上着 19:00-19:50 的课）高亮仍然正确落在这一节，而不是跳到下一门。

## 4. 逐项实现要求

### 4.1 `TodayPlan`（纯函数，必须单测）

签名建议（可微调，但**时间必须由参数注入**，禁止内部调 `System.currentTimeMillis()` / `LocalTime.now()`，否则无法单测）：

```kotlin
/** 今日一节课（小组件只读视图所需的最小字段）。 */
data class TodayItem(
    val startSection: Int,
    val endSection: Int,
    val courseName: String,
    val classroom: String?,
    val startMinute: Int,
    val endMinute: Int,
    val colorTag: Int,
)

/** 空态原因（AC-19 的文案来源）。 */
enum class EmptyReason { NONE, NO_TERM, NO_COURSE_TODAY }

data class TodayPlan(
    val items: List<TodayItem>,          // 已按 startSection 升序
    val nextIndex: Int?,                 // 高亮项下标；null = 无（全部结束或空）
    val overflowCount: Int,              // 超出展示上限的剩余门数（显示「还有 N 门」）
    val emptyReason: EmptyReason,
)

object TodayPlanBuilder {
    const val MAX_ITEMS = 4
    fun build(
        dayItems: List<TodayItem>,       // 调用方已完成「按天筛选」
        nowMinute: Int,
        hasTerm: Boolean = true,
    ): TodayPlan
}
```

**单测（`app/src/test/java/com/gould/xputimetable/widget/TodayPlanTest.kt`，≥ 9 例）**

| # | 场景 | 期望 |
|---|------|------|
| 1 | 今日 3 门（8:00/10:00/14:00） | items 按 startSection 升序，`nextIndex=0`（尚未结束的第一门） |
| 2 | 时间落在第 1 门中间（如 8:30） | `nextIndex=0`（**正在上的课仍高亮**，语义同 `shouldNotify`） |
| 3 | 前两门已结束（如 12:00 时，8:00 与 10:00 已过） | `nextIndex=2` |
| 4 | 全部已结束（如 21:00） | `nextIndex=null`，`emptyReason=NONE`（今日有课但已全部结束） |
| 5 | 今日无课 | `items` 空、`nextIndex=null`、`emptyReason=NO_COURSE_TODAY` |
| 6 | 无激活学期 | `emptyReason=NO_TERM`（优先级高于 NO_COURSE_TODAY） |
| 7 | 超过上限（6 门） | `items.size == MAX_ITEMS`、`overflowCount == 2` |
| 8 | 跨节连排（3-4 节一项） | 作为**一个** item，`startMinute/endMinute` 取 3 节起始与 4 节结束 |
| 9 | 边界：`nowMinute == endMinute` | 视为**已结束**（严格 `nowMinute < endMinute`），不高亮 |

### 4.2 Glance 内容（AC-17 / AC-19）

- 用 Glance 组件：`GlanceTheme`（来自 `glance-material3`）+ `Column`/`Row`/`Text`/`Box`。**不要**用 Compose 的 `Scaffold`/`LazyColumn` 等（Glance 里不存在）。
- 尺寸自适应（`LocalSize`，`DpSize`）：
  - 高 < 100dp：只显示**下一节**一行 + 「今日还有 N 门」；
  - 其余：标题「今天 · 周X」+ 最多 4 条列表（时间 `HH:mm` + 课名 + 教室），高亮项用**加粗/主题色底**（不要 emoji）。
- 空态（AC-19）：
  - `NO_COURSE_TODAY` → 主文案「**今天没有课**」+ 次文案「好好休息」；
  - `NO_TERM` → 「还没有课表」+ 「打开 App 导入」。
  - **今日有课但已全部结束**（`emptyReason = NONE` 且 `nextIndex == null`）→ 「**今天的课已全部结束**」
    （2026-09-17 真机补录：实现新增了该状态，语义正确——「没有课」与「课上完了」是两件事，规格已回写对齐）
- 图标：用项目既有 `R.drawable.lucide_*` 矢量资源（**不得**引入 emoji）。
- 整体点击 → 打开 App：`actionStartActivity<MainActivity>()`（图标与整卡都可点）。
- 文字一律 12–14sp、行距紧凑；**不得**出现横向滚动。

### 4.3 刷新机制（AC-18 + 跨天）

必须有**且只有**一个刷新入口 `WidgetRefresher.refreshAll(context)`（幂等，可重复调用）。触发源共 5 类：

| # | 触发源 | 落点 |
|---|--------|------|
| 1 | App 启动 | `TimetableApp.onCreate` |
| 2 | 数据变更（导入 commit / 课程保存 / 课程删除 / 按来源清理 / 学期保存或校正） | 统一走 §4.5 的 `onDataChanged` |
| 3 | 小组件被添加 / 尺寸变化 / 系统要求更新 | `TodayWidgetReceiver.onUpdate`（Glance 默认实现会渲染；确认 resize 后也会重绘） |
| 4 | **跨天** | `DailyWidgetRefreshWorker` 每日一次（00:05 起） |
| 5 | 提醒触发时刻（可选但推荐，成本极低） | 既有 `ReminderManager.onAlarmFired()` 之后顺手 `refreshAll`，让"下一节"高亮在课前准时翻页 |

**已知限制（写进代码注释，不必解决）**：两次刷新之间时间流逝不会自动重绘，所以"高亮"可能短暂过期；靠 #5 与用户打开 App 兜住。

### 4.4 元数据与隐私（硬要求）

`res/xml/today_widget_info.xml`：

```xml
<appwidget-provider
    android:minWidth="180dp"
    android:minHeight="110dp"
    android:targetCellWidth="3"        <!-- API 31+ 生效 -->
    android:targetCellHeight="2"
    android:minResizeWidth="110dp"
    android:minResizeHeight="110dp"
    android:resizeMode="horizontal|vertical"
    android:updatePeriodMillis="0"     <!-- 0 = 不用系统周期刷新，全部由 App/Worker 驱动（省电） -->
    android:initialLayout="@layout/today_widget_loading"
    android:previewLayout="@layout/today_widget_preview"
    android:widgetCategory="home_screen"   <!-- ★ 只上桌面，不上锁屏 -->
    android:description="@string/widget_description" />
```

- **`widgetCategory` 只能是 `home_screen`**：课程名/教室属于个人作息信息，不得出现在锁屏（与 AC-09「凭据与数据不出本机」的隐私精神一致）。
- 新增字符串资源：`widget_label`＝「今日课程」、`widget_description`＝「显示今天的课程与下一节课」（中文，无 emoji）。
- Selector 里显示的名字来自 **receiver 的 `android:label`**，所以 `AndroidManifest.xml` 的 receiver 必须写：
  `android:label="@string/widget_label"`，否则选择器里会显示包名/类名。
- 小组件**不得**发起任何网络请求、不得显示账号信息、不提供编辑入口（架构 §9.4：只读视图）。

### 4.5 数据变更后立即刷新（AC-18，避免 8 处重复）

现状有 8 个调用 `reminderManager.reschedule()` 的位置（启动 / 编辑保存 / 编辑删除 / 导入 commit / 清理 / 学期保存 / 改提醒开关 / 改提前分钟）。**不要**在每个位置各写一遍小组件刷新：

- 在 `AppContainer` 增加组合回调 `onDataChanged`（见 §3），把 AppNav 里注入给各 ViewModel 的 `{ reminderManager.reschedule() }` 换成 `{ container.onDataChanged() }`。
- 注意：**仅"数据变更类"触发点**需要刷新小组件（启动/编辑/导入/清理/学期）；提醒偏好变化（开关、提前分钟）不影响 widget 内容，可保持只重排闹钟。
- `refreshAll` 必须包 `runCatching`：小组件刷新失败绝不能让导入/保存失败（与既有 `rescheduleReminders` 的处理一致）。

## 9. 我方真机验收方法（交付后执行）

1. 长按桌面 → 添加小组件 → 找到「今日课程」→ 添加，确认**能正常渲染**（不白屏、不崩）
2. 期望内容：今日课程按时间列出 + 下一节高亮（当前 19:00 前后应高亮第 9 节那门，若有）
3. 在 App 内新增/编辑一门**今天**的课 → 保存 → **不重启 App、不下拉刷新** → 看桌面小组件是否已变化（AC-18）
4. 把该课改到**今天没有课**的状态（或临时清空今日课） → 小组件应显示「**今天没有课**」（AC-19），且不得列出非本周课程
5. 点小组件 → 应打开 App 并落在周视图
6. `adb shell dumpsys jobscheduler | grep -A3 xputimetable` → 应能看到每日刷新任务已入队
7. 拖拽改变小组件尺寸（2×2 / 4×2）→ 布局自适应不崩
8. 收尾：删除测试课，数据库回到 `MANUAL 1（高数）+ WEB 9`、17 条安排
